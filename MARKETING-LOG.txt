1. REPOSITORY AUDIT & DISCOVERABILITY BASELINE
================================================================================
- Organization: ellmos-ai
- Umbrella Ecosystem: open-bricks
- Primary Category: AI Infrastructure & Governance / Multi-Agent Policy Engine
- Core Positioning: Autonomous, reusable, local-first pointer registry for policies, rules, and decision candidates. Stores cryptographic metadata pointers and SHA-256 hashes referencing canonical sources rather than duplicating full text, ensuring local sources remain authoritative and discoverable even when disconnected from cloud sync or remote networks.
- Distinct Value Proposition:
  * Pointer-Only Storage: Strictly rejects full-text payload bodies, preventing cloud sync corruption and stale file drift.
  * Cryptographic Signed Delegation: Local Ed25519 signature verification for issuer-delegated decision candidates against pinned public trust stores without external PKI dependencies.
  * Fail-Closed Precedence & Advisory Guidance: Ambiguous, missing, or conflicting norms return status code 2 with advisory TOM-lm guidance and `automatic_authority: false`.
  * Effective Interaction Authority: Evaluates `governance-bound` (default), `user-sovereign`, and `chat-authority-only` modes with session override and project fallback.
  * 100% Local-First & Zero-Egress: Zero network sockets, zero unauthenticated telemetry, pure local filesystem execution (`~/.policy-registry/registry.json`).
- Sibling Ecosystem Integration: Pairs directly with `ellmos-ai/decision-clicker` as human writer & UI, `ellmos-ai/memoryhooker` for long-term memory, `ellmos-ai/ellmos-scheduler` for scheduled tasks, `ellmos-ai/lock-master` for concurrent agent locking, and developer tooling across `dev-bricks` and `open-bricks`.

2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Autonomous AI Agent Engineers & Swarm Operators (Codex, Claude Code, Gemini/Antigravity, Kimi)
   - Needs: Enable autonomous agents to discover, query, and respect project and system policies without inflating prompt context with thousands of lines of full-text rule documents.
   - Pain Points: Stuffing monolithic policy files into system prompts causes token exhaustion, hallucinated rule interpretations, and race conditions between concurrent agents.
   - Solution: Lightweight metadata pointer queries via CLI or MCP (`policy_search`, `policy_resolve`), fast scope inheritance matching, and SHA-256 integrity verification against canonical rule files.

2. Multi-Agent Governance & System Architects
   - Needs: Establish deterministic, auditable governance hierarchies spanning global, organization, and project scopes, with cryptographically verifiable delegation of authority.
   - Pain Points: Unclear precedence between overlapping guidelines, unverified agent permission claims, difficulty in revoking authority or tracing decisions back to human approval.
   - Solution: Cryptographic Ed25519 signed delegation verification (`resolve-delegation`), strict precedence hierarchy (exact > wildcard > parent > global), append-only rule materialization (`adopt`), and structured advisory TOM-lm fallback notices.

3. DevOps & CI/CD Pipeline Automation Engineers
   - Needs: Enforce compliance and governance checks in automated pipelines without cloud dependencies, external secrets managers, or network latency.
   - Pain Points: Cloud policy engines (AWS IAM, OPA Gatekeeper) require internet egress, remote credentials, or heavy background daemon processes that slow down builds and fail offline.
   - Solution: 100% offline, zero-egress Python CLI and library, instantaneous execution, exit code 0 on definitive resolution and exit code 2 on advisory conflict/missing state.

4. Enterprise Security, Privacy & Compliance Auditors
   - Needs: Verify that policy enforcement tooling adheres to strict zero-egress, unprivileged user mode, and permissive open-source licensing standards.
   - Pain Points: Third-party policy engines frequently aggregate decision telemetry in external clouds; storing full text in registries risks leaking confidential credentials or proprietary prompts.
   - Solution: Pointer-only storage (strictly rejects `content`, `payload`, `body`), 100% Local-First / Zero-Egress (INV-LOCAL-01), unprivileged RunAsInvoker non-elevation (INV-PRIV-07), 100% permissive open-source license audit (THIRD_PARTY_LICENSES.md), and codified 48h/5d security SLA (INV-SLA-10).

5. GOVERNANCE & RUNTIME INVARIANTS
================================================================================
- INV-LOCAL-01: 100% Local-First & Zero-Egress (Strictly local filesystem storage; zero external network calls, zero telemetry exfiltration).
- INV-PTR-02: Pointer-Only Architecture (Stores canonical URI references, SHA-256 hashes, scopes, priorities; strictly rejects full-text payload/body duplication).
- INV-CRYPTO-03: Ed25519 Cryptographic Delegation (Verifies issuer grants and delegate candidate signatures locally against pinned public trust stores without external PKI).
- INV-FAIL-04: Fail-Closed Advisory Fallback (Ambiguous, missing, or conflicting norms return exit code 2 with advisory TOM-lm guidance and `automatic_authority: false`).
- INV-APPEND-05: Append-Only Audited Rule Register (`adopt` materializes rules via immutable append-only rows; superseding records never delete historical evidence).
- INV-MODE-06: Effective Interaction Authority Modes (Evaluates `governance-bound` default, `user-sovereign`, and `chat-authority-only` with session override and project fallback).
- INV-PRIV-07: Unprivileged Non-Elevation / RunAsInvoker (Executes strictly within standard unprivileged user space without administrative or UAC elevation).
- INV-MAT-08: Multi-OS CI Testing Matrix (Automated cross-platform matrix testing on Windows, Linux, and macOS across Python 3.10, 3.11, 3.12, 3.13).
- INV-GATE-09: Strict CI Concurrency & Bytecode Gate (`cancel-in-progress: true` prevents redundant runner compute; whole-repo `compileall` ensures 100% bytecode validity).
- INV-SLA-10: Dual Security Response & Triage SLA (48-hour response acknowledgment and 5-business-day triage commitment with canonical security contacts).
